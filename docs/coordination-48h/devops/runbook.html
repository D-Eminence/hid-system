1. Rules for every change

  • Use the guarded helper from section 4 every time: plan, review the private manifest, then apply with --accepted-review-sha256 "<sha256>".
  • Don't start a backend release between a plan and its apply. Never run a website release and a backend release at the same time. Check with the owner that nothing is releasing before you plan.
  • Keep plans and review manifests private and out of Git. Remove TF_VAR_cloudflare_origin_secret from your shell after each session.
  • Don't rename or delete anything with "staging" in its name. Those are live production resources: hid-staging-* buckets, /hid/staging/* secrets and log groups.
  • Never put a private key or password in Git, tfvars, a ticket, chat or a command line.
  • Confirm the account first: aws sts get-caller-identity must show 659225405023. The state backend and lineage are in section 4. Stop if they differ.
  • If a plan shows anything different from what's described here, stop and send the owner the plan summary before you apply.
