Normal sign-in does not repeat NIN verification. The local synthetic enrollment verifier described in the next row exercises sign-in by HIDCode, including for a phone-only account, over HTTP for enrolled patients; it is not staging evidence. With D-Eminence/hid-system#39 (not yet deployed), sign-out also works after the access cookie has expired, by the refresh cookie and its CSRF token, and a portal that names itself in `X-HID-Client` (`staff-web`, `patient-web`) does not refresh or end the other portal's sign-in while refresh could renew it. Public NIN enrollment keys duplicates by the submitted NIN's keyed lookup. While the QoreID gate is closed (QoreID or NIN-only enrollment disabled, or QoreID paused), every NIN gets the same `503` before any lookup (ENR-4 step 1, D-Eminence/hid-system#68); with QoreID or NIN-only enrollment switched off (production, under N1), Identity's `503` says "New Health ID registration is not open yet. If you already have a Health ID, sign in." (the gateway passes it through, ADR-055), and `GET /api/v1/identity/patient-enrollments/availability` answers `{ "open": boolean }` from the same gate so Health-id can say so before it asks for a NIN (FE-4; Health-id reads it). Before 0093, with the gate open, a NIN already bound or pending was refused `409 NIN_ALREADY_REGISTERED` before QoreID was asked; since 0093 only a holder proof answers it (below). A new NIN is stored only after `summary.nin_check=verified`, `status.state=complete`, `status.status=verified`, an exact `nin.nin` match, and a numeric top-level `id` provider reference, and each QoreID lookup is charged to a per-network and platform-wide quota (0085). The adapter normalizes `nin.firstname`, `nin.lastname`, `nin.middlename`, `nin.birthdate`, `nin.gender`, `nin.phone`, `nin.photo`, and `nin.residence.address1`, `nin.residence.town`, `nin.residence.lga`, and `nin.residence.state` into a server-only registry profile. The QoreID phone is never automatically made the HID account contact. HID OTP proves control of the independently chosen phone or email; it is separate from QoreID identity verification and is not a holder-proof field. QoreID's empirically verified entitled sandbox NIN-only call differs from its [published NIN-with-NIN request](https://docs.qoreid.com/docs/nin-with-nin), which requires first and last names at the same path. QoreID also confirmed that numeric `expiresIn: 7200` means a 7,200-second access token lifetime. HID preserves the provider expiry and applies a 5,400-second internal maximum-use window, shortened further for a shorter provider lifetime. CAC Basic V2 endpoint access and its verified sparse RC/BN sandbox responses are empirically confirmed; complete profile, binding, and activation still need staging acceptance. See [the QoreID contract](QOREID_VERIFICATION_CONTRACT.md). The AWS CDK dependency audit remains a separate release gate while the official package still bundles vulnerable `brace-expansion`.

D-Eminence/hid-system#84 (ADR-062, migration 0093; merged to main, not deployed) changes this: each start is a new enrollment at `verify_holder`, start never answers `409 NIN_ALREADY_REGISTERED`, and a code sent by SMS to the phone the NIN record lists must be entered (`POST .../holder`, `POST .../holder/verify`) before the contact step. Only a correct code answers whether the NIN has a Health ID. Availability answers `{ "open", "online", "facility" }`. Staging sends email only, and production runs the online route only while a facility takes part (ADR-063), so until a facility is designated every deployed start answers `503 PATIENT_REGISTRATION_NOT_OPEN`. Health-id 55a50b0 does not know the holder step and cannot register a patient on 0093 (`INTERFACE_CONTRACT.md`, "The NIN holder step"). D-Eminence/hid-system#85 (ADR-063, migration 0094; merged to main, not deployed) adds the facility route: `GET .../participating-facilities`, `POST .../facility-code` (the desk code), the staff `POST /identity/assisted-verifications` and the admin designation `GET`/`POST /admin/facilities/:id/assisted-registration`. Health-id 55a50b0 has none of these screens (`INTERFACE_CONTRACT.md`, "Facility-assisted registration").
