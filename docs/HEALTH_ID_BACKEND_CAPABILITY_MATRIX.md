Public NIN enrollment uses the submitted NIN as the stable duplicate key only after `summary.nin_check=verified`, `status.state=complete`, `status.status=verified`, and an exact `nin.nin` match. The adapter normalizes `nin.firstname`, `nin.lastname`, `nin.middlename`, `nin.birthdate`, `nin.gender`, `nin.phone`, `nin.photo`, and `residence.address1`, `town`, `lga`, and `state` into a server-only registry profile. The QoreID phone is never automatically made the HID account contact. HID OTP proves control of the independently chosen phone or email; it is separate from QoreID identity verification and is not a holder-proof field. QoreID's empirically verified entitled sandbox NIN-only call differs from its [published NIN-with-NIN request](https://docs.qoreid.com/docs/nin-with-nin), which requires first and last names at the same path. QoreID also confirmed that numeric `expiresIn: 7200` means a 7,200-second access token lifetime. HID preserves the provider expiry and applies a 5,400-second internal maximum-use window, shortened further for a shorter provider lifetime. CAC onboarding still needs the QoreID CAC Basic V2 entitlement and a confirmed mapping for prefixed `RC`/`BN`/`IT` numbers. See [the QoreID contract](QOREID_VERIFICATION_CONTRACT.md). The AWS CDK dependency audit remains a separate release gate while the official package still bundles vulnerable `brace-expansion`.
