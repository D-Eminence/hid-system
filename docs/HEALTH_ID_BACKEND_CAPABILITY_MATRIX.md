# Health ID frontend to HID backend capability matrix

The PR #5 state below is a historical baseline. The subsequent backend gap
audit and resolved/remaining integration questions are recorded in
[the frontend backend gap audit](HEALTH_ID_FRONTEND_BACKEND_GAP_AUDIT.md) and
[open questions](OPEN-QUESTIONS.md). They include consent, facility session,
Lab and emergency contract corrections without claiming staging acceptance.

Reference: `D-Eminence/Health-id` public web and product routes (inspected at `8903e68`), `D-Eminence/hid-1.0` for historical behavior, and this repository as the authoritative implementation. This matrix records readiness of the executable PR #5 tree.

Public NIN enrollment uses the submitted NIN as the stable duplicate key only after `summary.nin_check=verified`, `status.state=complete`, `status.status=verified`, an exact `nin.nin` match, and a numeric top-level `id` provider reference. The adapter normalizes `nin.firstname`, `nin.lastname`, `nin.middlename`, `nin.birthdate`, `nin.gender`, `nin.phone`, `nin.photo`, and `nin.residence.address1`, `nin.residence.town`, `nin.residence.lga`, and `nin.residence.state` into a server-only registry profile. The QoreID phone is never automatically made the HID account contact. HID OTP proves control of the independently chosen phone or email; it is separate from QoreID identity verification and is not a holder-proof field. QoreID's empirically verified entitled sandbox NIN-only call differs from its [published NIN-with-NIN request](https://docs.qoreid.com/docs/nin-with-nin), which requires first and last names at the same path. QoreID also confirmed that numeric `expiresIn: 7200` means a 7,200-second access token lifetime. HID preserves the provider expiry and applies a 5,400-second internal maximum-use window, shortened further for a shorter provider lifetime. CAC Basic V2 endpoint access and its verified sparse RC/BN sandbox responses are empirically confirmed; complete profile, binding, and activation still need staging acceptance. See [the QoreID contract](QOREID_VERIFICATION_CONTRACT.md). The AWS CDK dependency audit remains a separate release gate while the official package still bundles vulnerable `brace-expansion`.
